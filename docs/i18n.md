# Languages

The site is available in English, French and Spanish. The player picks a language in the
footer of every page or in Settings; a first visit follows the languages of the browser.
Every text of the interface comes from a dictionary, so a page never mixes two languages.

## Where the choice lives

- `core/i18n/languages.ts`: the list of languages (`LANGUAGES`), each with its own name
  ("Français") and its locale for dates and numbers (`fr-FR`).
- `Preferences.language()`: the language shown. It is stored in the browser
  (`42chess.preferences`) and, when signed in, in the account (`preferences.language` of
  `PATCH /v1/users/me`; the backend accepts `en`, `fr` and `es`). Signing in on another
  browser brings the account's language with it. An account that never chose keeps the
  language the browser already shows.
- `public/theme.js` sets `<html lang>` before the first paint; `I18n.use()` keeps it in step
  afterwards, so screen readers pronounce the page in the right language.

## Dictionaries

The texts are TypeScript objects in `srcs/angular/42chess/src/app/i18n/<language>/`, one file
per area of the site (`game.ts`, `social.ts`, `pages.ts`...), gathered by each `index.ts`.

- English (`i18n/en`) is the reference and ships with the application. French and Spanish
  are separate chunks, loaded the first time they are picked.
- French and Spanish are typed as `Translation`, the shape of the English dictionary: a
  missing, extra or misspelt key is a compile error.
- A text takes parameters as `{{name}}`: `'Remove {{name}}'`.
- French uses *vous*, Spanish uses *tú*.

### Adding a text

1. Add the key to the English file of the area, then to the French and Spanish files at the
   same path. The build fails until all three have it.
2. Use it:
   - in a template wrapped in `<ng-container *transloco="let t">`: `{{ t('game.resign') }}`,
     `[heading]="t('history.none')"`, `t('social.friends.removeName', { name })`;
   - in a small inline template: `{{ 'app.language' | transloco }}`;
   - in TypeScript: `tr('game.resign')`. `tr` reads the current language, so a `computed`
     or a template that calls it follows a change of language at once. Keep the result in a
     `computed` rather than a plain field when it stays on screen.
3. Counted texts have a `one` and an `other` form, chosen by `Intl.PluralRules`:
   `trCount('game.watchers', count)` with `watchers: { one: '{{count}} spectator watching',
   other: '{{count}} spectators watching' }`.
4. Server codes (`errors.codes.<CODE>`, `chess.reasons.<CODE>`, achievements) are looked up
   with `trIfExists`, which returns `null` for an unknown code so the caller can fall back to
   the server's English message.

### Dates

Use the `localDate` pipe (`shared/ui/local-date.ts`) instead of Angular's `date` pipe: it
formats in the locale of the language shown ("2 novembre 2026"). It takes the same formats
and an optional time zone: `{{ updated | localDate: 'longDate' : 'UTC' }}`.

### Server messages

The API answers in English. `errorText()` (`core/api/error-text.ts`) shows the server message
as it is in English, and the shared text of its code (`errors.codes.<CODE>`) in French or
Spanish, then the explanation of the HTTP status, then the page's own fallback.

### Long pages

The Privacy Policy, the Terms of Service and the game rules are prose with links and
emphasis. Each keeps one block per language in its template
(`@switch (language()) { @case ('fr') {...} @case ('es') {...} @default {...} }`), so the
text reads naturally and keeps its markup. A change to one language must be made in the
other two.

What stays in English on purpose: PGN files (a file format with English tags), the server
logs, and the `42 Chess` name.

## Adding a language

1. Add it to `LANGUAGES` in `core/i18n/languages.ts` and register its Angular locale data in
   `core/i18n/i18n.ts`.
2. Copy `i18n/en` to `i18n/<code>`, type the index as `Translation`, translate every text,
   and add its loader to `LOADERS` in `i18n.ts`.
3. Add a `@case` to the long pages.
4. Allow the code in the backend (`users/user-preferences.ts`, the preferences DTO) with a
   migration of the `language` check, as `1793900000000-AddSpanishLanguage` does.

## Tests

- `i18n/dictionaries.spec.ts`: French and Spanish have exactly the English keys, every text
  is filled and uses only the English parameters, and every key that the templates and
  components ask for exists (it scans `src/app` for `t()`, `tr()`, `trIfExists()`,
  `trCount()` and the `transloco` pipe).
- `core/i18n/i18n.spec.ts`: switching language changes the texts, `<html lang>`, the date
  locale, the spoken moves, the results and the long pages.
- `shared/ui/language-select.spec.ts`: the footer list shows the saved language.
- `e2e/i18n.e2e.ts`: switching from the footer, keeping the choice after a reload, following
  the browser on a first visit, and bringing the account's language to another browser.
- `test/users-preferences.e2e-spec.ts` (backend): the account accepts `es`.

Unit tests run in English: `src/test-providers.ts` provides the dictionaries to every test.
